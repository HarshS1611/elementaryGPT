# elementaryGPT

A character-level GPT (decoder-only transformer) written from scratch in PyTorch and trained on the complete Sherlock Holmes stories. It continues any passage you give it in the voice of Conan Doyle.

Follows Andrej Karpathy's ["Let's build GPT"](https://karpathy.ai/zero-to-hero.html) lecture, with a different dataset and a larger model.

## Dataset

`sherlock.txt` holds all nine Sherlock Holmes books by Arthur Conan Doyle, from Project Gutenberg (public domain):

| Novels | Story collections |
|--------|-------------------|
| A Study in Scarlet (1887) | The Adventures of Sherlock Holmes (1892) |
| The Sign of the Four (1890) | The Memoirs of Sherlock Holmes (1894) |
| The Hound of the Baskervilles (1902) | The Return of Sherlock Holmes (1905) |
| The Valley of Fear (1915) | His Last Bow (1917) |
| | The Case-Book of Sherlock Holmes (1927) |

3,724,052 characters with a vocabulary of 101, about 3.4 times the Shakespeare file used in the lecture. Gutenberg's license headers and footers are removed, and curly quotes and em-dashes are converted to plain ASCII (`"`, `'`, `--`), so the model learns one quote character instead of three. The data is split 90% train, 10% validation, in order and without shuffling.

## Usage

**Train** (about 17 minutes on an Apple M3 Pro GPU; it picks CUDA, then Apple Silicon, then CPU):

```bash
python3 gpt.py
```

This writes `elementarygpt.pt` (the weights) and `samples.txt` (2,000 generated characters).

**Generate** with the trained model:

```bash
python3 generate.py                      # interactive session
python3 generate.py --prompt 'The case of the' --tokens 300 --seed 1    # one continuation
```

In the interactive session, type the opening of a passage and the model continues it. Settings can be typed anywhere in a line:

```
> The case of the /temp 0.5 /len 300
> /topk 20
> /help    /quit
```

- `/temp` sets the temperature (default 0.5). Lower values are safer and repeat more, higher values are livelier and messier. Measured on this model, the share of generated words that are real words from the books is 99.6% at 0.5, 96.4% at 0.8 and 93.0% at 1.0.
- `/len` sets how many characters to write, and `/topk` restricts sampling to the k likeliest characters at each step.
- The model continues text, it does not answer questions. Prompts in the style of the stories work best.

The lecture's configuration (384 dims, 6 heads, 6 layers, context 256, batch 64) would take about 3.5 hours for 20,000 steps on this GPU.

## How it works

- **Tokens.** Each of the 101 distinct characters is one token. Text is cut into random windows of 128 characters, and the target is the same window shifted one character ahead, so every position in a window is a training example.
- **Embeddings.** A token embedding says what each character is, and a position embedding says where it is, because attention by itself has no sense of order.
- **Causal self-attention.** Each position builds a query and compares it with the keys of itself and earlier positions only, enforced with a triangular mask. Scores are scaled by the square root of the head size, turned into weights with a softmax, and used to average the value vectors. Eight heads run in parallel and their outputs are mixed by a linear layer.
- **Block.** Attention, then a feed-forward layer applied to each position, each wrapped in LayerNorm before it and a residual connection after it.
- **Output.** A final LayerNorm and a linear layer give a score for each of the 101 characters at every position. Training minimizes cross-entropy with AdamW.
- **Generation.** One character is sampled at a time from the last position's scores and appended to the context, which is cropped to the last 128 characters. Temperature and top-k control the sampling.

## Notes from building this

- **Validation loss of 9.9.** The first full run ended with train loss 0.0095 and validation loss 9.9, worse than random guessing, and the samples looped on the same few characters. The cause was in `get_batch`: it created a new random generator with a fixed seed on every call, so every training step used the same batch of 32 windows, 0.12% of the text. The model memorized those, and the "train" loss reported during evaluation came from the same batch. The 22 tests at the time all passed, because each of them passed its own generator and never reached the buggy branch. Fix: draw from PyTorch's global random state. `test_get_batch_returns_a_different_batch_each_call` now fails if the bug returns.
- **Attention scaling and initialization.** Two details from the reference implementation improved the first working version (0.83M parameters, 5,000 steps, single runs): scaling attention scores by the head size instead of the embedding size (validation 1.66 to 1.63), and initializing every weight with standard deviation 0.02 (1.63 to 1.49). The initialization matters more than it looks: the untrained model starts near a uniform guess instead of a confident wrong one.
- **Passing tests were not enough.** Tests that check shapes, causality and loss decreasing all passed while training was broken. The causal-mask, residual, position-embedding and context-crop tests were each checked by deliberately breaking the code and confirming that exactly the intended test fails.

## Tests

```bash
python3 -m pytest tests/ -v
```

37 tests, run in about 3 seconds on tiny models:

- **Data:** vocabulary, encoding round trip, the train/validation split, batch shapes and shift, and that batches differ between calls.
- **Model:** attention and the full model never let a position see the future, the block has a residual connection, the model uses position information, output shapes, and the starting loss.
- **Training:** loss decreases, and loss estimation restores training mode.
- **Generation:** greedy sampling at temperature 0 and with top-k 1, top-k never samples outside the k likeliest, temperature widens the samples, prompt cleaning, context cropping, and settings typed inside a prompt.
